# LMS 요구사항 정의서

## 1. 문서 개요

- 시스템명: LMS (Learning Management System, 교육과정 관리 시스템)
- 목적: 교육과정 개설, 수강신청, 과제 제출·평가를 하나의 시스템에서 관리한다.
- 대상 사용자: 학습자, 강사, 관리자
- 기술 스택: Flutter (UI) + Spring Boot (REST API) + Oracle (DB)
- 작성 상태: 4주차 초안 (v0.1) — 멘토 검토 후 확정

## 2. 사용자 정의

| 구분  | 설명               | 주요 업무                        |
| --- | ---------------- | ---------------------------- |
| 학습자 | 교육을 수강하는 사용자     | 과정 조회, 수강신청/취소, 과제 제출, 진도 확인 |
| 강사  | 과정을 운영하는 사용자     | 과정 운영, 수강생 관리, 과제 출제·채점      |
| 관리자 | 시스템 전체를 관리하는 사용자 | 사용자·과정·공통코드 관리, 수강 승인, 통계 조회 |

## 4. 비기능 요구사항

- 보안: 비밀번호는 암호화하여 저장하고, 권한별로 화면·API 접근을 제한한다.
- 성능: 목록 조회는 페이징 처리하고, 조회 응답은 2초 이내를 목표로 한다.
- 데이터 무결성: 수강신청과 정원 차감은 하나의 트랜잭션으로 처리한다.
- 이력 관리: 모든 테이블에 등록자·등록일시·수정자·수정일시를 기록한다.
- 호환성: Flutter 화면과 Spring Boot REST API는 JSON으로 통신한다.

## 5. 제약 사항 및 가정

- 교육 목적의 간이 시스템으로, 결제와 외부 연동(SSO 등)은 범위에서 제외한다.
- 동영상 강의 재생, 시험 출제 기능은 1차 범위에서 제외한다.
- 첨부파일은 서버 로컬 경로에 저장하고, 파일 메타 정보만 DB에 보관한다.
