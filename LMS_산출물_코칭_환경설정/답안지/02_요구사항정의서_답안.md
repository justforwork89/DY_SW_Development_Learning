# LMS 요구사항 정의서 (1시간 미니판) — 답안

> 요구사항 ID는 실제 `LMS 요구사항 정의서.md`의 ID(LMS-001~012)를 그대로 써요.
> 실제 문서의 LMS-007은 "승인"과 "취소" 두 가지를 한 줄에 담고 있어서(한 줄 한 요구 위반) 007-1, 007-2로 나눴어요.

| ID | 사용자 | 요구 (한 줄에 하나) | 합격 기준 | 우선순위 | 화면 ID | API ID | 시험 ID |
|---|---|---|---|---|---|---|---|
| LMS-003 | 학습자 | 학습자가 과정을 이름·상태·기간으로 검색한다. | 검색어 "Flutter"를 넣으면 과정명에 "Flutter"가 들어간 과정만 보인다. 상태를 "모집중"으로 고르면 STATUS_CD=20인 과정만 보인다. 한 번에 10건씩 보인다. | 상 | LMS-C001 | API-001 | TC-001, TC-002 |
| LMS-006 | 학습자 | 학습자가 모집중인 과정을 수강신청한다. | 신청하면 ENROLL에 STATUS_CD=10(신청)으로 저장되고 MSG-001이 뜬다. 이미 신청한 과정이면 저장되지 않고 MSG-002가 뜬다. | 상 | LMS-E001 | API-002 | TC-003, TC-004 |
| LMS-007-1 | 관리자 | 관리자가 수강신청을 승인 또는 반려한다. | [승인]을 누르면 STATUS_CD가 20, [반려]를 누르면 30으로 바뀐다. 관리자가 아니면 403과 MSG-012가 온다. | 상 | LMS-M002 | API-004, API-005 | TC-005, TC-006 |
| LMS-007-2 | 학습자 | 학습자가 승인 전(신청) 상태의 내 신청을 취소한다. | 신청(10) 상태면 ENROLL 행이 지워지고 MSG-007이 뜬다. 승인(20)·반려(30)면 지워지지 않고 MSG-008이 뜬다. | 중 | LMS-E001, LMS-E002 | API-003, API-006 | TC-007, TC-008 |
| NFR-001 | 성능 | 과정 목록 조회는 2초 이내에 끝난다. | 과정 1,000건이 있을 때 API-001(10건 페이징) 응답 시간이 2초 이내다. | 중 | - | - | - |
| NFR-002 | 개인정보 | 다른 학습자의 수강신청 내역과 비밀번호는 볼 수 없다. | API-003은 로그인한 본인 USER_ID의 신청만 돌려준다. 어떤 API 응답에도 PASSWORD가 없다. | 상 | - | - | - |

※ 실제 요구사항의 "정원 초과 시 대기 처리"(LMS-006)는 미결 사항(대기열 구현 여부)이라 이번 범위에서 빼고, 정원이 차면 승인 단계에서 MSG-003으로 막아요.
