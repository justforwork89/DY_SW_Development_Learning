# 자료구조 이해

> [!warning] 💡
> **한 줄 정리**: 자료구조는 데이터를 쓰는 방식에 맞춰 고르는 정리 상자예요. 순서대로 쓰면 리스트·큐, 되돌리기는 스택, 빠른 검색은 해시·트리, 관계 표현은 그래프를 써요.

## 1. 자료구조란?

자료구조는 **데이터를 어떤 모양으로 정리해 둘지 정하는 방법**이에요. 방 정리에 비유하면, 옷은 서랍에 차곡차곡, 책은 책장에 번호순으로, 접시는 위로 쌓아 두잖아요. 물건마다 꺼내 쓰는 방식이 달라서 보관 방법도 달라요. 데이터도 **어떻게 꺼내 쓰느냐에 따라 알맞은 보관 방법**이 있고, 그게 자료구조예요.

자료구조를 잘 고르면 같은 일을 훨씬 빠르게 처리할 수 있어요. 예를 들어 학생 1만 명 중에서 "학번 2024123"을 찾을 때, 처음부터 한 명씩 보면 최대 1만 번을 확인해야 해요. 반면 학번표(해시)를 써 두면 한 번에 찾아요.

## 2. 대표적인 자료구조

| 자료구조 | 쉬운 비유 | 특징 | 어디에 쓰일까? |
| --- | --- | --- | --- |
| **배열 (Array)** | 번호 붙은 사물함 | 번호로 바로 꺼냄. 크기가 정해져 있음 | 성적표 점수 목록, 이미지 픽셀 |
| **리스트 (List)** | 기차 칸 연결 | 중간에 넣고 빼기 쉬움. 크기가 자유로움 | 장바구니 목록, 화면의 게시글 목록 |
| **스택 (Stack)** | 쌓아 둔 접시 | 마지막에 넣은 게 먼저 나옴 (후입선출) | 뒤로 가기 버튼, Ctrl+Z 되돌리기 |
| **큐 (Queue)** | 매점 줄서기 | 먼저 온 게 먼저 나감 (선입선출) | 프린터 인쇄 대기, 채팅 메시지 순서, 콜센터 대기 |
| **해시 / 맵 (Hash, Map)** | 이름표 붙은 사물함 | 이름(키)으로 바로 찾음. 매우 빠름 | 로그인 정보 확인, 학번으로 학생 찾기, 캐시 |
| **트리 (Tree)** | 가계도, 폴더 구조 | 위에서 아래로 가지를 뻗음 | 컴퓨터 폴더, 회사 조직도, DB 인덱스(B-Tree) |
| **힙 (Heap)** | 응급실 대기 | 가장 급한(크거나 작은) 것부터 꺼냄 | 우선순위 작업 처리, 실시간 순위 |
| **그래프 (Graph)** | 지하철 노선도 | 점과 선으로 연결 관계를 표현 | 길찾기 내비게이션, SNS 친구 추천 |

## 3. 실습 과정에서는 어디에 나올까?

이 과정에서 쓰는 코드에도 이미 자료구조가 들어 있어요.

### ① Java / Spring Boot

DB에서 학생 목록을 조회하면 `List<StudentDTO>`로 받아요. 이게 리스트예요. JSON으로 주고받는 데이터는 `Map<String, Object>`처럼 키와 값을 짝지은 맵 구조이고, 공통 코드를 미리 불러 둘 때도 맵(해시)을 써요.

### ② Flutter / Dart

화면에 목록을 보여주는 `ListView`가 `List` 데이터를 받아 그려요. 서버에서 받은 JSON도 `Map<String, dynamic>`으로 바뀌어요. 그리고 화면 이동(Navigator)은 스택 구조라서, 새 화면은 위에 쌓이고 뒤로 가면 맨 위 화면부터 빠져요.

### ③ Oracle DB

인덱스를 만들면 내부적으로 **B-Tree**라는 트리 구조가 생겨요. 그래서 수만 건 중에서도 빠르게 찾을 수 있어요.

## 4. 함께 알아두면 좋은 개념

**알고리즘**은 데이터를 처리하는 순서(방법)예요. 정렬하기나 찾기가 그 예예요. 자료구조가 "어떻게 정리해 둘까"라면, 알고리즘은 "정리된 걸 어떻게 처리할까"예요. 둘은 늘 같이 다녀요.

**시간 복잡도 (Big-O)**는 데이터가 많아질수록 처리 시간이 얼마나 늘어나는지를 나타내요. 예를 들어 O(1)은 데이터가 많아도 한 번에 끝나고(해시), O(n)은 데이터 수만큼 걸려요(처음부터 하나씩 찾기).
