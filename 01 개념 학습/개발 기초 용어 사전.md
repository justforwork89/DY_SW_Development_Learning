# 개발 기초 용어 사전

개발하다가 모르는 말이 나오면 여기서 먼저 찾아보세요. 이 과정의 기술 스택(Java · Spring Boot · Oracle · Flutter)과 산출물 용어 위주로 정리했어요. 새로 알게 된 용어는 계속 추가합니다.

> [!warning] 💡
> 쉬운 비유: **Flutter 앱**은 식당 홀(손님이 보는 화면), **Spring Boot**는 주방(실제로 요리하는 곳), **Oracle DB**는 창고(재료 보관), **REST API**는 홀과 주방 사이의 주문서예요.

## 1. 기본 개발 용어

| 용어               | 쉬운 설명                                             |
| ---------------- | ------------------------------------------------- |
| 프론트엔드 (Frontend) | 사용자가 눈으로 보고 누르는 화면 쪽. 이 과정에서는 Flutter             |
| 백엔드 (Backend)    | 화면 뒤에서 데이터를 처리하는 서버 쪽. 이 과정에서는 Spring Boot        |
| 서버 / 클라이언트       | 요청을 받아 처리해 주는 쪽 / 요청을 보내는 쪽 (앱, 브라우저)             |
| 프레임워크            | 개발에 필요한 뼈대와 규칙을 미리 만들어 둔 틀 (Spring Boot, Flutter) |
| 라이브러리            | 필요한 기능을 가져다 쓰는 코드 모음                              |
| 빌드 (Build)       | 작성한 코드를 실행 가능한 프로그램으로 만드는 일                       |
| 디버깅 (Debugging)  | 버그(오류)를 찾아서 고치는 일                                 |
| 로그 (Log)         | 프로그램이 동작하며 남기는 기록. 오류 원인 찾을 때 가장 먼저 봄             |
| 예외 (Exception)   | 실행 중 생긴 오류 상황. try-catch로 처리                      |
| 리팩터링             | 기능은 그대로 두고 코드를 읽기 좋게 정리하는 일                       |

## 2. 통신 · API

| 용어 | 쉬운 설명 |
|---|---|
| API | 프로그램끼리 서로 요청하고 답하는 약속된 창구 |
| REST API | 주소(URL)와 방식(GET/POST 등)으로 요청하는 API 설계 방식 |
| 엔드포인트 (Endpoint) | API의 구체적인 주소. 예: /api/students |
| HTTP 메서드 | GET(조회), POST(등록), PUT(수정), DELETE(삭제) |
| 요청 / 응답 (Request / Response) | 클라이언트가 보내는 것 / 서버가 돌려주는 것 |
| JSON | 데이터를 \{ 이름: 값 \} 모양으로 주고받는 텍스트 형식 |
| 상태 코드 | 200 성공, 400 잘못된 요청, 404 없음, 500 서버 오류 |
| 파라미터 | 요청할 때 함께 보내는 값 (입력값) |

## 3. DB · SQL (Oracle)

| 용어 | 쉬운 설명 |
|---|---|
| DB / DBMS | 데이터를 모아 둔 곳 / 그것을 관리하는 프로그램 (Oracle) |
| 테이블 | 줄과 칸으로 된 데이터 표 |
| 컬럼 / 로우 | 표의 세로 항목 / 가로 한 줄(한 건의 데이터) |
| PK (기본키) | 줄마다 겹치지 않는 고유 번호 (학번처럼) |
| FK (외래키) | 다른 테이블의 PK를 가리키는 연결 고리 |
| 인덱스 | 책의 색인처럼 검색을 빠르게 해 주는 장치 |
| CRUD | Create(등록) · Read(조회) · Update(수정) · Delete(삭제) |
| DDL / DML | 표의 구조를 만드는 문장(CREATE) / 데이터를 다루는 문장(SELECT, INSERT 등) |
| JOIN | 여러 테이블을 연결해서 함께 조회하는 것 |
| 트랜잭션 | 여러 작업을 한 덩어리로 묶어 전부 성공 또는 전부 취소하는 것 |
| COMMIT / ROLLBACK | 작업을 확정 / 취소하는 명령 |
| ERD | 테이블 간의 관계를 그림으로 그린 설계도 |

## 4. Spring Boot (백엔드)

| 용어 | 쉬운 설명 |
|---|---|
| Controller | 요청을 받아 어디로 넘길지 정하는 입구 |
| Service | 실제 업무 로직(계산, 검사)을 처리하는 곳 |
| Repository / Mapper | DB와 직접 대화하는 곳 (이 과정에서는 MyBatis Mapper) |
| DTO / VO | 데이터를 담아 옮기는 상자 역할의 객체 |
| MyBatis | SQL을 XML 등에 적어두고 자바에서 불러 쓰게 해 주는 도구 |
| 의존성 주입 (DI) | 필요한 객체를 직접 만들지 않고 스프링이 넣어주는 것 |
| 어노테이션 | @Controller, @Service처럼 클래스 역할을 알려주는 표시 |
| Lombok | getter/setter 같은 반복 코드를 자동으로 만들어 주는 도구 |
| Validation | 입력값이 올바른지 검사하는 기능 |

## 5. Flutter · Dart (프론트엔드)

| 용어 | 쉬운 설명 |
|---|---|
| Widget | 화면을 이루는 모든 조각 (버튼, 글자, 목록 등) |
| StatelessWidget / StatefulWidget | 변하지 않는 화면 조각 / 값이 바뀌면 다시 그려지는 화면 조각 |
| State (상태) | 화면이 기억하는 값. 바뀌면 화면도 바뀜 |
| MVVM | Model(데이터) · View(화면) · ViewModel(둘 사이 중개) 로 역할을 나눈 구조 |
| 데이터 바인딩 | 데이터와 화면을 연결해 값이 바뀌면 화면이 자동 갱신되는 것 |
| Future / async / await | 시간이 걸리는 작업(서버 통신)을 기다리는 방법 |
| 직렬화 / 역직렬화 | 객체 ↔ JSON 변환 |

## 6. 산출물 · 협업 용어

| 용어 | 쉬운 설명 |
|---|---|
| 요구사항 정의서 | 만들어야 할 기능을 ID, 설명, 우선순위로 적은 문서 |
| 화면설계서 | 화면 모양과 동작, 연결 API를 그린 문서 |
| 테이블 정의서 | 테이블·컬럼·키 정보를 정리한 문서 (DDL 포함) |
| 테스트 케이스 | 입력값과 예상 결과를 미리 정해 두고 확인하는 시험 항목 |
| Git / GitHub | 코드 변경 이력을 관리하는 도구 / 그것을 올려두는 저장소 사이트 |
| 커밋 (Commit) | 변경 내용을 한 번 저장해 기록으로 남기는 것 |
| 브랜치 (Branch) | 원본을 건드리지 않고 따로 작업하는 가지 |
| Push / Pull | 내 코드를 저장소에 올리기 / 저장소의 최신 코드를 받기 |
| 스프린트 | 정해진 짧은 기간 동안 목표를 정해 진행하는 작업 단위 (이 과정은 주 단위) |
