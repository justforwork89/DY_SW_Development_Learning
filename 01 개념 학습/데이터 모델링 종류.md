# 데이터 모델링 종류

> [!warning] 💡
> **한 줄 정리**: 실무에서는 개념 → 논리 → 물리 순서로 관계형 모델을 설계하는 일이 가장 기본이에요. 분석용이면 차원 모델을, 대용량이나 비정형 데이터면 NoSQL을 추가로 써요.

데이터 모델링은 **데이터를 어떻게 담을지 설계도를 그리는 일**이에요. 집을 지을 때 바로 벽돌을 쌓지 않고 설계도부터 그리는 것과 같아요. 크게 두 갈래로 나눠 볼 수 있어요. 하나는 설계를 하는 **순서(단계)**, 다른 하나는 데이터를 담는 **모양(구조)**이에요.

## 1. 단계별 분류: 설계하는 순서

| 단계 | 쉬운 설명 | 학교 예시 | 산출물 |
| --- | --- | --- | --- |
| **개념적 모델링** | 무엇을 저장할지 큰 그림을 그려요 | "학생이 있고, 과목이 있고, 학생은 과목을 수강한다" | 개념 ERD |
| **논리적 모델링** | 항목과 관계를 구체적으로 정해요 | 학생(학번, 이름, 학년), 과목(과목코드, 과목명), PK·FK 결정, 정규화 | 논리 ERD |
| **물리적 모델링** | 실제 DB에 맞춰 만들어요 | `STUDENT_ID NUMBER(10)`, 인덱스 설정, Oracle용 DDL 작성 | 테이블 정의서, DDL |

집에 비유하면 개념적 모델링은 "방 3개, 거실 1개" 정도의 스케치예요. 논리적 모델링은 방 크기와 문 위치를 정한 평면도이고, 물리적 모델링은 자재와 치수까지 적은 시공 도면이에요. 실습 과정의 **ERD → 테이블 정의서 → DDL** 흐름이 이 순서와 같아요.

## 2. 구조별 분류: 데이터를 담는 모양

### ① 계층형 모델

회사 조직도처럼 위에서 아래로 내려가는 나무 구조예요. 부모 하나에 자식이 여럿 붙어요. 오래된 방식이라 지금은 거의 안 써요.

### ② 네트워크형 모델

계층형과 달리 자식이 부모를 여럿 가질 수 있는 그물 구조예요. 복잡해서 지금은 잘 쓰지 않아요.

### ③ 관계형 모델 (가장 많이 씀)

데이터를 **표(테이블)**에 담고, 표끼리 키(PK·FK)로 연결해요. Oracle, MySQL, PostgreSQL이 이 방식이고, SQL로 다뤄요. 이 과정에서 배우는 게 바로 이 모델이에요.

### ④ 객체지향 모델

자바의 클래스와 객체처럼 데이터와 기능을 한 덩어리로 묶어 저장해요. 순수한 형태로는 드물고, 관계형과 섞은 "객체-관계형"이 쓰여요.

### ⑤ 차원 모델 (분석용)

매출 분석이나 보고서용 데이터 창고(데이터 웨어하우스)에서 써요. 가운데에 "판매 기록" 같은 **사실(Fact) 테이블**을 두고, 주변에 "날짜·상품·지점" 같은 **차원(Dimension) 테이블**을 붙여요. 별 모양이면 스타 스키마, 차원이 더 잘게 나뉘면 스노우플레이크 스키마라고 불러요.

### ⑥ NoSQL 모델

표로 담기 어려운 데이터를 위한 방식이에요.

| 종류 | 모양 | 예 |
| --- | --- | --- |
| 키-값 | 사물함 번호와 내용물 | Redis (로그인 세션, 캐시) |
| 문서형 | JSON 문서를 통째로 저장 | MongoDB |
| 컬럼형 | 세로줄 단위로 저장해 대용량 분석에 강함 | Cassandra, HBase |
| 그래프형 | 점(사람)과 선(관계)으로 저장 | Neo4j (SNS 친구 추천) |

## 3. 함께 알아두면 좋은 개념

**정규화**는 같은 데이터가 여러 곳에 중복 저장되지 않게 표를 나누는 작업이에요. 예를 들어 학생 표에 담임 선생님 전화번호를 매번 적지 않고 선생님 표를 따로 만들어요.

**반정규화**는 반대로, 조회 속도를 위해 일부러 표를 합치거나 중복을 허용하는 거예요.
